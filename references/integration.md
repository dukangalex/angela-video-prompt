# 链路衔接方法

本工作流在整条视频生产链里居中：前面是镜头设计，后面是审片。上下游在本仓库里只保留方法，不绑定任何外部技能或工具——各项目用自己现有的镜头设计与审片机制对接。

```
镜头设计（生成前）
  场景/情绪 → 导演风格匹配 → 镜头决策 → 可执行 prompt
  （单镜头默认；2-3 镜仅用于 reveal-reaction-action 链、confrontation、
   有意义的环境揭示、地点/时间变化）
        │
        ▼
本工作流（生成中）
  六段式模板归位 → 生成 → 多段快照接续 → ffmpeg 拼接
        │
        ▼
审片（生成后）
  single / variants / sequence 三模式
  → 技术完整性 + 连续性 + 生成痕迹检查
  → 发布结论（ready / post_fix / regenerate_segment / reject）
  → 最小返修方案（定位到具体时间段，如"以 00:03.2 为参考重生成 00:04.2–00:05.8"）
```

## 衔接规则
- 镜头设计的输出 prompt 按本工作流六段式模板字段归位后，再交用户定稿。
- 审片时把提示词、分镜、参考图和创作意图一起给审片环节，避免把有意的叙事变化误判为连续性错误。
- 返修结论若要求"局部重生成"，回到本工作流第 3 步，只重跑该段（快照接续该段的前一段）。
- 观察与推断分离：审片报告里无法确认的不写成事实，标待确认。

> 方法来源：上游作者的 CueShot 链路设计（cinematic-shot-design → muse-video-prompt-skill → ai-director-video-review），自有化时保留链路方法、去除对作者自研技能的依赖。
